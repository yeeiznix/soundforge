# SoundForge — Release Notes G2

**Gate:** G2 — Signal Graph + Mixer UI (native routing engine + Android editor
surfaces). **Tag:** `g2-complete`.

## Deliverables

A typed signal-graph core with a routing desk for per-node gain/pan/mute/solo,
a static desk evaluator (topological order, per-output route gains), a
lock-free command queue for audio-thread-safe mutation, and Android editor
screens for the signal graph and mixer — all layered additively on the G0/G1
shell. Schema stays `project_v2` (schemaVersion 2) with one additive refresh
during P7 (see below).

### P1 — Schema v2.1 hardening (`73dec4f`)
- Audit `enum` drift fix (4 → 13 actions) to match the native validator + real
  documents (G2-1).
- `SF_E_FILE_TOO_LARGE` (7) + `read_file_capped()` pre-parse byte cap (8 MiB)
  on file/`from_json` load paths (SEC-1a/1b).
- `kMaxAuditEntries = 1000` FIFO audit cap + `isfinite()` gates on mixer inputs
  (SEC-1c/1d).
- `schema_golden_v2.json` regenerated byte-identical to
  `native/data/schemas/project_schema.json`, SHA-256 pins in pytest (ORC-A).

### P2 — Typed graph core (`10a35f3`)
- `graph_internal.hpp`: `SignalNode` / `SignalEdge` / `SignalGraphDoc` with
  invariants, replacing the opaque JSON blob in the project doc
  (behavior-preserving).

### P3 — Graph mutators C ABI (`c16d9db`, `sf_graph.h` 7 exports)
- `sf_graph_add_node`, `sf_graph_remove_node`, `sf_graph_add_edge`,
  `sf_graph_remove_edge`, `sf_graph_set_mixer`, `sf_graph_set_preset`,
  `sf_graph_apply_batch`.
- New audit actions: `project.create`, `graph.addNode`, `graph.removeNode`,
  `graph.addEdge`, `graph.removeEdge`, `graph.setMixer`, `graph.setPreset`
  (audit enum 13).

### P4 — Routing engine (`32517a2`, 3 exports)
- `sf_graph_validate` (structural report: warnings + errors, cycle detection),
  `sf_graph_topological_order` (Kahn; `SF_E_SCHEMA` on cycle),
  `sf_graph_evaluate_mixer` (per-output route static gain coefficients, mute /
  solo semantics, clip indicator).
- Evaluator output is labeled a *static routing-desk estimate*, not DSP truth —
  G3 owns the mixing law (G2-5).

### P5 — SfCommandQueue (`6c476ce`, 6 exports)
- Classic Lamport SPSC lock-free ring, capacity 256, 176-B slots; seq advances
  only on acceptance; `sf_graph_apply_batch` funnels through the same
  commit-validation code path as the sync mutators, stop-on-first-error.
- 15 tests: 10k-threaded stress, overflow rejection, partial-apply batch
  contract (G2-3).
- Documented env limitation: ASan cannot map its shadow region under
  proot/Termux (`sanitizer_allocator_primary64.h` init CHECK) — a one-off
  UBSan build (`-fsanitize=undefined -fno-sanitize-recover=all`) is the
  sanitizer substitute; 118/118 green at P5.

### P6 — JNI bridge + Kotlin models (`940ead4`, 16 → 25 exports)
- `jni_bridge.cpp` +9 sf_graph passthroughs (add/remove node/edge, set mixer/
  preset, validate, topological order, evaluate mixer), same
  try/catch/`log_boundary_exception` guard as G1.
- `NativeBridge.kt` +9 external mirrors, byte-identical names per PLAN_G2 §4.6.
- `SignalKt.kt`: typed mirrors `SignalGraphKt` / `SignalNodeKt` / `SignalEdgeKt`
  + tolerant parser; `SF_NODE_*` constants.
- `UiState.Ready` gains `handle` + `signalGraph`; `nativeMutex` private→internal
  (ONE mutex per handle, not per VM); new `refreshState()` re-parses the
  committed document after graph commits (called outside `withLock` — Mutex is
  not reentrant).
- `SignalGraphViewModel` + `MixerViewModel` with the g1.1-hardened
  bind/commit/close shape; close() only joins the shared mutex — destroy stays
  owned by `ProjectViewModel` (no double-destroy).

### P7 — Editors + Nav wiring + wire fix (`5f3db3b`)
- `SignalEditorScreen`: add node with kind picker (source / processor / output /
  bus), add connection with from/to dropdowns + port fields, node/edge lists
  with delete, preset chip, inline errors (local validation + native
  `lastEditError`).
- `MixerScreen`: per-channel strips — gain slider (−60..24 dB), pan slider
  (−1..1), mute/solo chips, Routing preview card (evaluate JSON, pretty, with
  Re-evaluate).
- `NavGraph`: hoists the two graph ViewModels and binds them to the
  activity-scoped `ProjectViewModel` once per Ready (idempotent).
- **Wire fix (additive schema refresh, schemaVersion stays 2):** review found
  mixer `gainDb`/`pan` and edge ids never crossed the v2 wire — mixer values
  were silently lost on save/reopen and `removeEdge` could not resolve a target
  (G2 §1.1 requires per-node mixer state to persist). Fix: node mixers now
  carry `gainDb`/`pan`; edges carry their `id`; codec (write+read), hand-rolled
  validator, python mirror (reads the canonical file — no copy), golden,
  digest pins, and Kotlin mirrors updated in the same commit; new
  `GraphMixerAndEdgeIdsSurviveRoundTrip` test. `dspPresetRef` and edge ports
  remain intentionally off-wire.
